Problemas Encontrados

Alta P001

God Object: coreManager.ts (934 linhas)

Arquivo: main/coreManager.ts Risco: Manutenibilidade

Problema: Um único arquivo gerencia spawn de Node Core, Python sidecar, economia, bridge TTS, dedup de logs, estratégias de kill e decisões de startup. Viola SRP.

Impacto: Qualquer mudança em subprocesso requer modificar este gigante. Regressões frequentes.

Afeta: Desenvolvedores — manutenção lenta e arriscada.

O que vai mudar: Extrair para 5 módulos: node-core-launcher.ts, economy-lifecycle.ts, tts-bridge.ts, port-utils.ts, startup-decision.ts.
Ganho esperado: Complexidade ciclomática de ~60 para ~10 por módulo.
Alta S001

Token de sessão exposto em process.env

Arquivo: main/index.ts:252 Risco: Segurança

Problema: MOMAI_SESSION_TOKEN é setado em process.env e herdado por subprocessos (Node Core, Python, extensões). Crash dumps e logs podem expor o token.

Impacto: Atacante com acesso ao sistema extrai o token e autentica requisições à API.

Afeta: Usuários finais — risco de sequestro de sessão.

O que vai mudar: Passar token via argumento de CLI ou pipe anônimo.
Ganho esperado: Elimina vazamento de token para subprocessos.
Alta S002

Extensões herdam token de sessão via process.env

Arquivo: node-core/services/extension-host-manager.js:89 Risco: Segurança

Problema: startPersistent() spawna child process com env: { ...process.env }. Toda extensão tem acesso irrestrito à API.

Impacto: Extensão maliciosa pode exfiltrar o token e acessar todos os endpoints.

Afeta: Usuários finais — quebra do modelo de segurança.

O que vai mudar: Filtrar env vars com whitelist de vars seguras.
Ganho esperado: Isolamento real entre extensão e core.
Alta S003

Path traversal no storage de extensões

Arquivo: extension-host-worker.js:25-41 Risco: Segurança

Problema: storage.get(key) faz path.join(storageBase, `${key}.json`) sem sanitizar key. Extensão pode ler qualquer arquivo no DATA_DIR.

Impacto: Extensão pode sobrescrever messages.json, store.json ou dados de outras extensões.

Afeta: Usuários finais — corrupção de dados.

O que vai mudar: Validar key com regex (alfanumérico + underscore).
Ganho esperado: Elimina vetor de path traversal.
Alta S004

XSS via srcDoc em preview HTML do LLM

Arquivo: renderer/chat/HtmlPreviewCard.tsx:26 Risco: Segurança

Problema: HTML gerado pelo LLM renderizado em iframe srcDoc com sandbox="allow-scripts". Backend comprometido → XSS no renderer.

Impacto: Potencial comprometimento total do Electron renderer.

Afeta: Usuários finais.

O que vai mudar: Sanitizar HTML com DOMPurify antes de passar ao srcDoc.
Ganho esperado: Elimina risco de XSS.
Alta S005

Credenciais Trello em plaintext no .env

Arquivo: apps/momai/.env Risco: Segurança

Problema: TRELLO_API_KEY, TRELLO_TOKEN, TRELLO_DEFAULT_BOARD_ID em texto plano. Gitignored, mas vulnerável a backup, exfiltração ou erro humano.

Impacto: Vazamento dá acesso completo ao board Trello do projeto.

Afeta: Organização.

O que vai mudar: Rotacionar credenciais; armazenar via Electron safeStorage.
Ganho esperado: Elimina risco de vazamento.
Alta M001

30+ blocos catch {} vazios engolem erros

Arquivo: coreManager.ts, backend-manager.ts, bootstrap/, etc. Risco: Manutenibilidade

Problema: Múltiplos catch {} silenciosamente engolem erros em shutdown, scans, operações de arquivo e subprocessos.

Impacto: Erros críticos invisíveis. Debugging de produção impossível.

Afeta: Desenvolvedores.

O que vai mudar: Adicionar log (warn/error) em todos os catches vazios.
Ganho esperado: Visibilidade completa de erros.
Alta M002

I/O síncrono em IPC handler bloqueia UI

Arquivo: main/lexical-search.ts:69-75 Risco: Performance

Problema: runLexicalNoteSearch usa readFileSync em IPC handler. Cada leitura síncrona bloqueia o main process.

Impacto: UI congela durante busca textual (~3s com muitas notas).

Afeta: Usuários finais — experiência de busca travada.

O que vai mudar: Substituir por fs.promises.readFile com concorrência limitada.
Ganho esperado: UI responsiva durante buscas (elimina freeze de ~3s).
Alta N001

promptText não inicializado se promptRegistry for nulo

Arquivo: node-core/chat-service.js:1191-1207 Risco: Qualidade de Resposta

Problema: promptText atribuído dentro de if (promptRegistry && ...) mas usado incondicionalmente depois. Se promptRegistry for nulo, prompt de sistema vazio.

Impacto: LLM recebe instrução de sistema vazia → respostas erráticas.

Afeta: Usuários finais — qualidade de resposta degradada.

O que vai mudar: Adicionar fallback: promptText || DEFAULT_SYSTEM_PROMPT.
Ganho esperado: Prompt de sistema sempre presente.
Alta PY001

Modelo Whisper carregado 3x na memória (OOM risk)

Arquivo: core/voice.py, detector.py Risco: Performance / Estabilidade

Problema: Três caminhos de código carregam modelos Whisper independentes. No pior caso, 3 instâncias ocupam >3GB de RAM.

Impacto: OOM em sistemas com 8GB RAM. App trava.

Afeta: Usuários finais com hardware modesto.

O que vai mudar: Singleton factory em app_state que retorna instância única do modelo.
Ganho esperado: Reduz uso de RAM de ~3GB para ~1GB.
Alta PY002

SQLite sem check_same_thread=False e sem WAL

Arquivo: core/database/models.py:59-63 Risco: Estabilidade

Problema: SQLAlchemy engine sem check_same_thread=False e sem PRAGMA journal_mode=WAL. Session chamado de múltiplas threads.

Impacto: ProgrammingError: SQLite objects created in a thread... em acesso concorrente.

Afeta: Usuários finais — erros aleatórios de banco.

O que vai mudar: Adicionar check_same_thread=False, NullPool, PRAGMA WAL.
Ganho esperado: Elimina erro de thread em SQLite.
Alta PY003

WebSocket thread-unsafe + blocking em rota async

Arquivo: core/api/routes/voice.py, app_state.py Risco: Estabilidade

Problema: active_websockets é list acessada de múltiplas threads sem lock. /quick-transcribe bloqueia por 30s em rota síncrona.

Impacto: Corrupção de lista + thread pool exaurido → server 503.

Afeta: Usuários finais — voice pipeline instável.

O que vai mudar: Lock na lista de WS + converter rota para async com to_thread().
Ganho esperado: Server responsivo durante transcrição longa.
