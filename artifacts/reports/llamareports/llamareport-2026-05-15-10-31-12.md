## Mudanças por Release (somente releases com mudanças relevantes listadas)

### Release b9165 - 2026-05-15

Última release. Inclui `ci : fix transform of top . entry in release archive` e `llama-eval : add AIME 2026 dataset support`. Nenhuma mudança crítica no backend.

### Release b9151 - 2026-05-14

- **HIP: RDNA3 mma FA, faster AMD transpose, tune AMD (#22880)**
  - Adiciona suporte RDNA3 ao kernel CUDA mma FA (matrix multiply-accumulate Flash Attention)
  - Usa tiles de 32 unidades lógicas para headsizes que dividem por 32 (FP16), 16 para outros (FP32)
  - Kernel tuning para RDNA3, RDNA4 e CDNA1
  - Head sizes até 256 para CDNA
  - **Benchmarks:**
    - Radeon 8060S: llama 1B Q4_0 pp512: **+91%** (1042 → 1989 t/s em batch 512)
    - Radeon 8060S: llama 8B Q4_0 pp512: **+18%** (245 → 289 t/s em batch 512)
    - RX 9060 XT: llama 8B Q4_0 pp512: **+12%** (506 → 565 t/s em batch 512)
    - MI100: llama 8B Q4_0 pp512: **+22%** (556 → 679 t/s em batch 16)
    - MI100: gemma 2B Q4_0 pp512: **+70%** (3387 → 5747 t/s em batch 512)
  - Relevância: 🔴 Alta (impacta diretamente performance em GPUs AMD via HIP)

- **vulkan: fix matmul integer pipeline selection (#23005)**
  - Corrige pipeline selection introduzido em #22693 que quebrava pipelines integer
  - Fixes #22992
  - Relevância: 🔴 Alta (bug fix crítico para Vulkan com quantização integer)

- **server, webui: accept continue_final_message flag for vLLM API compat (#23012)**
  - Compatibilidade com vLLM API para continue generation
  - Relevância: 🟡 Média (para compatibilidade de API)

- **SYCL: fix multi-GPU system RAM exhaustion (#21597)**
  - Corrige exaustão de RAM em sistemas multi-GPU SYCL
  - Relevância: 🟢 Baixa (MomAI não usa SYCL)

### Release b9143 - 2026-05-14

- **vulkan: Check shared memory size for mmq shaders (#22693)**
  - Calcula shared memory usage para shaders mmq, escolhe tile sizes menores quando não cabem
  - Fixes #22690 (crash em GPUs com shared memory limitado)
  - Relevância: 🔴 Alta (previne crash no Vulkan em GPUs low-end)

- **vulkan: Fix Windows performance regression on Intel GPU BF16 workloads for Xe2 (#22461)**
  - Corrige regressão de performance em Windows com Intel Arc GPUs (B580, B390)
  - Windows não expõe BF16 via Vulkan, então coopmat BF16 não está disponível
  - Usa `l_warptile` somente quando coopmat BF16 está realmente disponível
  - **Benchmarks:**
    - Arc B580 (Windows): pp512 **+8.2%** (1702 → 1842 t/s)
    - UX7-368H (Windows): pp512 **+8.8%** (653 → 712 t/s)
  - Relevância: 🟡 Média (melhoria em Intel Arc, não AMD)

- **server: support Vertex AI compatible API (#22545)**
  - Adiciona API compatível com Vertex AI
  - Relevância: 🟢 Baixa

## Recomendação de Versão Específica

### A) Atualizar para a última versão (b9165)

**Benefícios concretos para MomAI:**

1. **HIP RDNA3 mma FA (#22880)** - Se MomAI for usado com GPUs AMD via HIP, ganhos de **+12% a +91%** em prefill em GPUs RDNA3/4 e CDNA1
2. **Vulkan shared memory check (#22693)** - **Previene crashes** no Vulkan backend em GPUs com shared memory limitado
3. **Vulkan matmul integer pipeline fix (#23005)** - **Corrige pipeline selection** para quantização integer no Vulkan
4. **Intel Arc BF16 fix (#22461)** - Performance **+8-9%** em Intel Arc (Windows)
5. **Device buffers (#22679)** - Economia de VRAM mantendo checkpoints em device memory
6. **Asymmetric FA support (#22589)** - Mais flexibilidade de tipos K/V no Flash Attention

**Riscos identificados:**
- Nenhum breaking change identificado na API do server
- Nenhuma mudança que afete o modelo de slots do llama-server
- Nenhuma regressão reportada nos benchmarks fornecidos
- A versão b9165 foi publicada hoje (15/05/2026), então é recente, mas as PRs foram testadas individualmente

**Veredito: 🔥 Atualizar para b9165**

## Plano de Ação

1. **Alterar `MOMAI_LLAMA_VERSION`** no `.env` de `b8996` para `b9165`
2. **Rodar `hydrate-bin.ps1`** manualmente para baixar os novos binários
3. **Verificar build:** `pnpm --filter momai build` e confirmar que `validate-llama-package.js` passa
4. **Testar com `pnpm dev`:**
   - Verificar se o Vulkan backend sobe corretamente
   - Verificar `llama-server --version` para confirmar b9165 nos dois backends
5. **Validar com modelo Qwen:**
   - Performance (tok/s)
   - Slots paralelos (múltiplas conversas)
   - Estabilidade (sem crashes após uso prolongado)
6. **Commit:** Se tudo ok, fazer commit da atualização dos binários e da mudança de versão
