Usuário VÊ S004

LLM pode injetar HTML malicioso que o usuário vê e interage

Onde: renderer/chat/HtmlPreviewCard.tsx:26 Risco: XSS — código arbitrário no renderer

HTML gerado pelo LLM é renderizado em iframe srcDoc. Se o backend for comprometido, o usuário pode ver e interagir com uma página maliciosa.

Usuário vê: Página HTML adulterada, possível phishing ou execução de scripts.
Correção: Sanitizar com DOMPurify antes de renderizar.
Usuário VÊ M002

Busca textual congela a interface por segundos

Onde: main/lexical-search.ts:69-75 Risco: UI freeze de ~3s

readFileSync em IPC handler bloqueia o event loop do Electron. Cada nota é lida do disco de forma síncrona.

Usuário vê: Tela congelada durante busca. Animação de loading trava.
Correção: Usar fs.promises.readFile com concorrência limitada.
Usuário VÊ R001

App todo some em tela branca se qualquer componente quebrar

Onde: renderer/main.tsx Risco: Zero resiliência

Nenhum Error Boundary envolve a aplicação React. Um único erro não tratado em qualquer componente derruba a UI inteira.

Usuário vê: Tela branca. Perde o que estava fazendo.
Correção: Adicionar <ErrorBoundary> na raiz do App.
Usuário VÊ R002

Mensagem aparece na conversa errada ao trocar de thread rápido

Onde: hooks/useChatActions.ts:111-408 Risco: Mensagens fora de contexto

sendChatMessage faz fetch sem AbortSignal. Se o usuário troca de thread ou envia nova mensagem, o stream antigo continua em background.

Usuário vê: Mensagem aparece em conversa que não é a atual.
Correção: AbortController por requisição + abortar ao iniciar nova.
Usuário VÊ N001

LLM responde de forma estranha ou sem personalidade

Onde: node-core/chat-service.js:1191-1207 Risco: Prompt de sistema silenciosamente vazio

Se promptRegistry.buildSystemPrompt não estiver disponível, promptText fica undefined e o LLM recebe instrução vazia.

Usuário vê: Respostas genéricas, sem seguir as instruções de comportamento do MomAI.
Correção: Adicionar fallback com DEFAULT_SYSTEM_PROMPT.
Usuário VÊ N002

Passos de ferramentas (tool steps) somem da resposta

Onde: node-core/chat-service.js:689-690 vs 1033-1034 Risco: Variáveis sombreadas

toolSteps e activeSkill são redeclaradas dentro do bloco try, sombreando as declarações externas. Hooks beforeModel populam as externas, mas as internas são usadas na resposta.

Usuário vê: Steps de "buscando na web..." ou "consultando memória..." somem do chat.
Correção: Remover as declarações let duplicadas internas.
Usuário VÊ PY001

App pode travar por falta de memória (OOM)

Onde: core/voice.py + detector.py Risco: 3 modelos Whisper carregados simultaneamente

Três caminhos de código carregam modelos Whisper independentes. No pior caso, >3GB de RAM para algo que deveria usar ~1GB.

Usuário vê: App fecha ou trava em PCs com 8GB de RAM.
Correção: Singleton factory no app_state — única instância do modelo.
Usuário VÊ PY002

Erro aleatório de banco de dados "SQLite objects created in a thread"

Onde: core/database/models.py:59-63 Risco: Concorrência quebra SQLite

Engine SQLAlchemy sem check_same_thread=False e sem WAL mode. Sessões criadas de múltiplas threads quebram.

Usuário vê: Erro aleatório "ProgrammingError" — app não salva configuração.
Correção: check_same_thread=False + PRAGMA journal_mode=WAL + NullPool.
Usuário VÊ PY003

Voice pipeline falha ou para de funcionar

Onde: core/api/routes/voice.py + app_state.py Risco: Thread safety + bloqueio

active_websockets é uma lista acessada de múltiplas threads sem lock. /quick-transcribe bloqueia 30s em rota síncrona, exaurindo o thread pool.

Usuário vê: Comando de voz não funciona. Server responde 503. Reconhecimento trava.
Correção: Lock na lista + converter rota para async com to_thread().
Usuário VÊ PY004

Servidor fica indisponível durante gravação de áudio longa

Onde: core/api/routes/voice.py:128-145 Risco: Thread pool exaurido

/quick-transcribe é síncrono e bloqueia 30s. Sob carga, todas as threads do pool são esgotadas.

Usuário vê: 503 Service Unavailable ao tentar usar o app durante gravação longa.
Correção: Converter para async def + asyncio.to_thread().
Usuário VÊ PY005

Erros no app mostram detalhes técnicos feios (stack trace)

Onde: core/middleware/error_handler.py Risco: Vazamento de informação

sanitize_message() foi implementada e testada mas nunca conectada ao exception handler. Erros retornam detalhes internos.

Usuário vê: Mensagens de erro com nomes de arquivo e paths internos.
Correção: Conectar sanitize_message ao global exception handler.
Usuário VÊ S007

App pode crashar por mensagem malformada entre processos

Onde: main/coreManager.ts:420, 478 Risco: IPC sem validação

Todas as mensagens entre Node Core e Electron são cast para any. Mensagem inesperada → TypeError em runtime.

Usuário vê: App fecha sem aviso. Funcionalidade para de funcionar.

Usuário VÊ M001

Erros acontecem mas ninguém sabe — app quebra silenciosamente

Onde: coreManager.ts, backend-manager.ts, bootstrap/ Risco: 30+ catch {} vazios

Blocos catch {} engolem erros em shutdown, scans, operações de arquivo. Falhas passam despercebidas e se acumulam.

Usuário vê: Funcionalidade para de funcionar sem explicação. Reiniciar o app "resolve".
Correção: Adicionar log (warn/error) em todos os catches vazios.
Usuário VÊ M003

Notas ficam cada vez mais lentas com o tempo

Onde: main/notesService.ts Risco: O(n) I/O em cada operação

Toda operação lê o JSON inteiro do índice. Escrita salva arquivo completo. Com 500 notas, operações demoram ~200ms; com 2000 notas, ~1s.

Usuário vê: Listar, criar e buscar notas fica progressivamente mais lento.
Correção: Cache em memória + escrita diferida (debounce).

Usuário SENTE M004

App faz polling pesado a cada 5 segundos — drena bateria

Onde: main/economyService.ts:183-185 Risco: CPU + bateria

Polling a cada 5s: 2 requisições HTTP + scan de processos + idle check. Em notebook, trava CPU em estado ativo desnecessariamente.

Usuário sente: Bateria descarrega mais rápido. CPU fica em 0.5-1% constante.
Correção: Aumentar intervalo para 15-30s ou usar evento-driven (WebSocket).
Usuário SENTE R003

Streaming de resposta dá pequenas travadas visuais

Onde: features/chat/chatReducer.ts:76 Risco: GC pressure

Cada token no streaming cria [...prev] (cópia do array inteiro). Centenas de tokens por mensagem geram milhares de alocações.

Usuário sente: Pequenos micro-stutters durante streaming de resposta longa.
Correção: Usar concat ou immer para evitar alocações repetidas.

Usuário sente: PC lento, fans girando alto, app demora para responder.
Correção: Singleton factory — carga única do modelo Whisper.
Usuário SENTE M005

App fica mais lento após vários dias de uso (memory leak)

Onde: main/coreManager.ts:86-98 Risco: Listeners acumulados

Listeners de minimize/restore são adicionados sem remoção a cada restart do backend. Com o tempo, centenas de handlers disparam por evento.

Usuário sente: App fica lerdo com o passar dos dias. Minimizar/restaurar janela fica mais pesado.
Correção: Remover listeners antes de readicionar.

19 useEffect hooks em um único componente. Ordem de execução imprevisível causa re-renders em cascata.

Usuário CORRE RISCO S001

Token de sessão pode vazar para outros processos no PC

Onde: main/index.ts:252 Risco: Sequestro de sessão

MOMAI_SESSION_TOKEN em process.env é herdado por Node Core, Python e extensões. Crash dumps e logs expõem o token.

Risco do usuário: Qualquer processo malicioso no PC pode ler o token e acessar a API.
Correção: Passar token via argumento de CLI ou pipe.
Usuário CORRE RISCO S002

Extensão instalada pode acessar tudo que o app pode

Onde: node-core/extension-host-manager.js:89 Risco: Extensão maliciosa

Extensões herdam process.env com o token de sessão. Qualquer extensão tem acesso irrestrito à API.

Risco do usuário: Extensão aparentemente inofensiva pode exfiltrar dados ou comandos.
Correção: Filtrar env vars com whitelist.
Usuário CORRE RISCO S003

Extensão pode corromper dados de outras extensões

Onde: node-core/extension-host-worker.js:25-41 Risco: Path traversal

storage.get(key) não sanitiza o parâmetro key — extensão pode ler/escrever arquivos fora do seu diretório.

Risco do usuário: Extensão pode sobrescrever configurações ou mensagens salvas.
Correção: Validar key com regex (alfanumérico + underscore).
Usuário CORRE RISCO S006

Token de sessão visível em logs de rede

Onde: useChatWebSocket.ts + ws-auth.js + auth.py Risco: Token via query param

Token passado como ?token=... na URL de upgrade WebSocket. Logado por proxies, servidores, visível em Referer headers.

Risco do usuário: Token pode vazar para logs de acesso de rede ou extensões de browser.
Correção: Mover token para header Authorization: Bearer.
Usuário CORRE RISCO N004

Dados de hardware do PC expostos para o frontend

Onde: node-core/api/routes/settings.routes.js:34 Risco: Privacidade

GET /settings retorna store.settings completo — RAM total, VRAM total, e outros dados internos vão para o frontend.

Risco do usuário: Informações do hardware expostas. Em futuro próximo, pode incluir dados mais sensíveis.
Correção: Aplicar filterToEditableSettings também no GET.
Usuário CORRE RISCO N005

Dados de extensões podem ser lidos sem autenticação

Onde: node-core/api/router.js:8 Risco: Rota pública

/extensions/events é rota pública (sem auth). Stream SSE de eventos de extensões pode conter dados que o usuário considera privados.

Risco do usuário: Qualquer processo local pode escutar eventos de extensões.
Correção: Adicionar autenticação ao endpoint.
