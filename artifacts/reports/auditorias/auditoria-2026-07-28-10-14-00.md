# Relatório de Auditoria - MomAIOS

**Data:** 28 de Julho de 2026
**Escopo:** Completo (todo o monorepo)
**Versão analisada:** 1.6.0
**Tipo de auditoria:** Segurança, Performance, Arquitetura, Manutenibilidade, Cobertura de Testes

---

## Sumário Executivo

Esta auditoria analisou o monorepo MomAIOS — um assistente virtual local-first com Electron, React, Node.js e Python/FastAPI. Foram examinados **614 arquivos fonte** distribuídos em 4 aplicações, 1 pacote compartilhado e dezenas de módulos de serviço.

**Total de problemas encontrados:** 37
- **Críticos:** 1
- **Altos:** 6
- **Médios:** 14
- **Baixos:** 16

### Principais Descobertas

1. **Violação de regra arquitetural crítica**: Código específico do WhatsApp (`whatsapp-channel.js`) existe no código principal do Node Core, violando a política de auto-contimento de extensões.
2. **Token de sessão vaza em logs de autenticação WebSocket**: Os primeiros 12 caracteres do token e o resultado da comparação são logados.
3. **`sanitizeError` subutilizado**: Um sanitizador de erros bem projetado é usado em apenas 1 dos 15+ endpoints que retornam erros.
4. **Memoização anulada por função `t` instável**: O hook `useMemo` em `ContainerChat` depende de `[t]` que muda a cada render, zerando o cache.
5. **Mais de 40 eventos customizados não tipados**: O barramento de eventos via `window.dispatchEvent` não tem type safety, subscription tracking ou escopo.
6. **Três serviços usam dict bruto em vez de Pydantic**: `chat_voice.py` e `settings.py` aceitam `dict` sem validação.
7. **Extensa área sem testes**: Feature de Notes (~5000+ linhas, 21 arquivos) tem cobertura zero.

## Problemas Críticos

### C-01: Violação da Regra de Auto-Contimento de Extensões

**Arquivo:** `apps/momai/scripts/node-core/utils/whatsapp-channel.js`
**Linhas:** 1-26

**O problema:** O arquivo `whatsapp-channel.js` contém funções utilitárias específicas do WhatsApp (`resolveWhatsAppContactJid`, `resolveWhatsAppChannel`) no código principal do Node Core. Isso viola diretamente a regra documentada em `.opencode/rules/extension-ui-no-leak.md` que proíbe código específico de extensão no app principal.

**Riscos:**
- Arquitetural: Viola o princípio de auto-contimento de skills
- Manutenibilidade: Se outra extensão precisar de lógica similar, criaria mais vazamentos
- Portabilidade: Impede que a extensão WhatsApp seja mantida em seu próprio repositório sem depender do core

**Impacto prático:** Qualquer modificação na lógica de canais do WhatsApp requer alteração no repositório principal. A extensão não pode operar de forma independente.

**O que está afetando:** Desenvolvedores que mantêm a extensão WhatsApp e a equipe do core.

**O que vai mudar:** O código deve ser movido para dentro da extensão WhatsApp e acessado via mecanismos genéricos do sistema de extensões.

**Soluções possíveis:**
1. Mover as funções para `apps/momai/data/extensions/whatsapp/` e acessar via API da extensão
2. Implementar um hook genérico de "channel resolution" no manifest da skill
3. Remover o arquivo e duplicar a lógica na extensão WhatsApp

**Solução recomendada:** (1) — Mover para a extensão WhatsApp e expor via `manifest.routes[]`. Isso mantém a extensão auto-contida e segue a arquitetura estabelecida.

## Problemas de Alta Severidade

### H-01: Vazamento de Token em Logs de Autenticação WebSocket

**Arquivo:** `apps/momai/scripts/node-core/middleware/ws-auth.js`
**Linhas:** 161-162

**O problema:**
```javascript
info(`[WS] Rejected: provided="${provided?.slice(0, 12)}..." expected="${expected?.slice(0, 12)}..."`)
info(`[WS] Full token comparison: provided=${provided === expected}`)
```

Os primeiros 12 caracteres (25% do token de 64 chars) e o resultado da comparação são logados toda vez que uma conexão WebSocket é rejeitada.

**Riscos:** Vazamento de informação sensível. 12 caracteres hexadecimais = 48 bits de entropia expostos. Um atacante com acesso aos logs (ex: leitura de `%APPDATA%/MomAI/logs`) reduz o espaço de busca significativamente.

**Impacto prático:** Em ambiente de produção, logs podem ser inspecionados por malware ou usuários mal-intencionados com acesso ao sistema de arquivos.

**O que está afetando:** Usuários finais (risco de segurança dos dados locais).

**O que vai mudar:** Remover o log do token ou substituir por um hash seguro.

**Solução recomendada:** Remover completamente o log de token. Se necessário para debugging em dev, usar `process.env.NODE_ENV === 'development'`.

### H-02: Sanitizador de Erros Subutilizado

**Arquivo:** `apps/momai/scripts/node-core/utils/error-sanitizer.js`
**Arquivos afetados:**
- `extensions.routes.js:1729` — `err.message` bruto
- `extensions.routes.js:1677` — `err.message` bruto
- `chat.routes.js:161` — `String(err)` bruto

**O problema:** O `sanitizeError` foi implementado com uma whitelist de mensagens seguras, detecção de stack traces e paths, e limite de 100 caracteres — mas é usado em **apenas 1** dos múltiplos endpoints que retornam erros.

**Riscos:** Vazamento de paths do sistema, nomes de arquivos, versões de dependências e estrutura interna em respostas de erro.

**Impacto prático:** Em caso de falha em qualquer um dos endpoints não protegidos, o cliente recebe detalhes internos do servidor (ex: `ENOENT: C:\Users\wesle\dev\momai\apps\momai\data\...`).

**O que está afetando:** Usuários finais que encontram erros (informações do sistema expostas).

**Solução recomendada:** Aplicar `sanitizeError` em todos os `catch` handlers que retornam `err.message` para o cliente.

### H-03: Variáveis de Ambiente `HOST`/`PORT` Genéricas

**Arquivo:** `apps/momai/src/main/constants.ts`
**Linhas:** 8-9

**O problema:**
```typescript
export const API_HOST = process.env.HOST || DEFAULT_HOST
export const API_PORT = parseInt(process.env.PORT || String(DEFAULT_PORT))
```

Os nomes `HOST` e `PORT` são extremamente genéricos. Ferramentas como `create-react-app`, Vite e outras também usam `PORT`. Um parent process ou variável de ambiente global pode sobrescrever inesperadamente.

**Riscos:** Conexão a um servidor não intencional se `HOST` for definido como um IP externo.

**Impacto prático:** Potencial de redirecionamento de tráfego da API em ambientes compartilhados.

**Solução recomendada:** Renomear para `MOMAI_API_HOST` e `MOMAI_API_PORT` e validar que o host resolve para endereço loopback.

---

### H-04: Eventos Customizados sem Type Safety (~40+ eventos)

**Arquivos afetados:** Múltiplos arquivos no renderer (App.tsx, hooks, components, views)

**O problema:** O barramento de eventos via `window.dispatchEvent(new CustomEvent(...))` é usado extensivamente (~40+ nomes de eventos únicos) sem:
- Tipagem do `detail`
- Subscription tracking (qualquer componente escuta qualquer evento)
- Escopo (eventos são globais no `window`)
- Garantia de cleanup

**Riscos:**
- **Memory leaks**: Listeners não removidos causam vazamento de componentes
- **Debugging difícil**: Fluxo de dados opaco, necessidade de grep global para entender
- **Race conditions**: Eventos em sequência não têm garantia de ordem de processamento

**Impacto prático:** Desenvolvedores gastam tempo significativo rastreando bugs de estado causados por eventos fora de ordem.

**Solução recomendada:** Substituir por um event emitter tipado (ex: o padrão `observabilityStore.ts`) ou usar Zustand/estado compartilhado para os casos mais comuns.

---

### H-05: Feature de Notes sem Testes (~5000+ linhas)

**Arquivo:** `apps/momai/src/renderer/src/features/notes/`
**Arquivos:** 21 arquivos (NotesView.tsx:920 linhas + hooks + componentes + utils)

**O problema:** A feature completa de Notes — que inclui editor CodeMirror, busca semântica, wikilinks, gerenciamento de arquivos — não tem **nenhum teste unitário ou de integração**.

**Riscos:** Regressões silenciosas, dificuldade de refatoração, bugs em produção não detectados.

**Impacto prático:** Qualquer alteração na feature de Notes requer teste manual completo. Bugs podem chegar aos usuários.

**Solução recomendada:** Implementar testes para os hooks principais (`useNotes`, `useWikiLinks`) e o componente `NotesView` (pelo menos renderização e interações básicas).

---

### H-06: Dependência Circular `api.ts` ↔ `ttsService.ts`

**Arquivos:**
- `apps/momai/src/renderer/src/services/api.ts` — importa de `ttsService.ts`
- `apps/momai/src/renderer/src/services/ttsService.ts` — importa de `api.ts`

**O problema:** `api.ts` tem import estático de `ttsService.ts` (linha 358) enquanto `ttsService.ts` importa `updateTtsStatus` de `api.ts` (linha 32). A importação dinâmica em `api.ts:346` tenta mitigar, mas a estática já cria a dependência circular.

**Riscos:** Módulos podem ser indefinidos no momento da importação (undefined ou partially initialized). Comportamento imprevisível em builds otimizados (tree-shaking).

**Solução recomendada:** Extrair `updateTtsStatus` para um módulo separado ou usar injeção de dependência.

## Problemas de Média Severidade

### M-01: `useMemo` Anulado por Função `t` Instável

**Arquivo:** `apps/momai/src/renderer/src/components/ContainerChat.tsx`
**Linhas:** 258-289

**O problema:** `useMemo` com dependência `[t]` onde `t` (do `useI18n()`) é uma nova função a cada render porque `useI18n` usa `useCallback([locale])`. O `useMemo` nunca funciona — recalcula em todo render.

**Impacto:** Performance degradada, shuffle de sugestões a cada render causa flicker visual.

**Solução:** Tornar `t` estável via ref ou separar o locale como dependência nos `useMemo`.

---

### M-02: IPC Genérico Expõe Ataque XSS

**Arquivo:** `apps/momai/src/preload/index.ts`
**Linhas:** 389-402

**O problema:** Métodos genéricos `invoke`, `send`, `on` expõem **todos** os canais permitidos a qualquer código renderer. Se existir XSS no renderer, atacante pode chamar qualquer canal.

**Solução:** Remover métodos genéricos e expor apenas funções nomeadas com parâmetros tipados.

---

### M-03: Sem Limite de Reinicialização do Node Core

**Arquivo:** `apps/momai/src/main/coreManager.ts`
**Linhas:** 828-835

**O problema:** O Node Core não tem limite máximo de tentativas de restart (diferente do Python sidecar que tem `PYTHON_RUNTIME_RESTART_MAX = 3`). Se o core falha persistentemente, o app reinicia infinitamente.

**Solução:** Adicionar `NODE_CORE_RESTART_MAX = 3` e notificar o usuário se excedido.

---

### M-04: Tray Menu sem `sandbox: true` Explícito

**Arquivo:** `apps/momai/src/main/services/tray-menu-window.ts`
**Linhas:** 32-45

**O problema:** A janela do tray menu não explicita `sandbox: true`, `contextIsolation: true` ou `nodeIntegration: false`. Embora os defaults do Electron sejam seguros, a explicitação é defesa em profundidade.

**Solução:** Adicionar `sandbox: true` às webPreferences.

---

### M-05: Proteção contra Path Traversal Fraca em Assets de Extensão

**Arquivo:** `apps/momai/src/main/renderer-static-server.ts`
**Linhas:** 65-80

**O problema:** A proteção bloqueia apenas `..` e `\\` literais. Não protege contra null byte injection, Unicode normalization ou paths absolutos.

**Solução:** Usar `path.resolve()` + `path.relative()` para verificação de containment (já existe `resolveSafePath` no mesmo arquivo).

---

### M-06: `authFetch` sem Timeout em Pontos Críticos

**Arquivo:** `apps/momai/src/main/windowManager.ts`
**Linhas:** 432-456

**O problema:** O handler `restore` faz `await authFetch(...)` sem AbortController/timeout. Se o backend estiver pendente, bloqueia a abertura da janela por tempo indeterminado.

**Solução:** Adicionar AbortController com timeout de 5-10s.

---

### M-07: `uncaughtException` Loga mas Não Finaliza Processo

**Arquivo:** `apps/momai/src/main/index.ts`
**Linhas:** 93-99

**O problema:** O handler de `uncaughtException` apenas loga e continua executando em estado potencialmente corrompido.

**Solução:** Chamar `app.exit(1)` após logar, ou delegar para sequência de shutdown.

---

### M-08: Erro em `sanitize_message` — Parâmetro `message` Ignorado

**Arquivo:** `apps/core/utils/error_handler.py`
**Linha:** 35

**O problema:**
```python
return fallback if is_safe_message(fallback) else "Internal server error"
```
A função verifica `fallback` (sempre seguro) em vez de `message`. Em produção, sempre retorna "Internal server error" independente do erro real.

**Nota:** Embora o comportamento atual seja funcionalmente seguro (nunca vaza info), ele impede debugging remoto. Para um app local-first, isso é aceitável mas pode frustrar usuários avançados.

**Solução:** Trocar `fallback` por `message` na verificação.

---

### M-09: `chat_voice.py` e `settings.py` Usam `dict` Bruto sem Validação

**Arquivos:** `apps/core/api/routes/chat_voice.py:24`, `apps/core/api/routes/settings.py:35`

**O problema:** Dois endpoints aceitam `data: dict` / `patch: dict` sem modelo Pydantic. Qualquer chave/valor é aceito sem validação de tipo.

**Risco:** Dados malformados podem causar erros 500 ou comportamento inesperado.

**Solução:** Criar modelos Pydantic para ambos os endpoints.

---

### M-10: Singleton TTS sem Thread Safety

**Arquivo:** `apps/core/services/voice/tts.py`
**Linhas:** 199-202

**O problema:** O padrão singleton do `TTSManager` verifica `_instance` sem lock. Duas threads podem criar instâncias simultaneamente.

**Solução:** Adicionar `threading.Lock()` ao redor da verificação.

---

### M-11: Configurações Duplicadas em `pyproject.toml`

**Arquivo:** `apps/core/pyproject.toml`
**Linhas:** 49-54

**O problema:** `[dependency-groups]` duplica dependências dev com versões diferentes, podendo causar conflitos.

**Solução:** Simplificar removendo `[dependency-groups]` e usando apenas `[project.optional-dependencies]`.

---

### M-12: Componente `ContextUsageRing` Cria WebSocket a Cada Montagem

**Arquivo:** `apps/momai/src/renderer/src/components/ContainerChat.tsx`
**Linhas:** 57-99

**O problema:** O componente `ContextUsageRing` abre nova conexão WebSocket a cada mount/unmount. Se o contexto ring é alternado múltiplas vezes, conexões são abertas/fechadas repetidamente.

**Solução:** Usar WebSocket singleton ou compartilhar conexão com o hook `useChatWebSocket`.

---

### M-13: `@ts-ignore`/`@ts-expect-error` em 11 Ocorrências

**Arquivos:** Múltiplos (useChat.ts, ContainerChat.tsx, etc.)

**O problema:** 11 supressões de erro TypeScript mascaram problemas reais de tipagem na interface com o preload bridge.

**Solução:** Tipar corretamente o `window.api` e remover as supressões.

---

### M-14: Logs com `console.log` em Produção (100+ ocorrências)

**Arquivo:** Múltiplos (NotificationOverlay.tsx, diversos)

**O problema:** `console.log` (não `console.debug`) é usado extensivamente. Em produção, esses logs poluem o console e podem conter dados de estado da UI.

**Solução:** Substituir por `console.debug` ou serviço de logging com guard de ambiente.

## Análise de Segurança

### Superfície de Ataque

| Camada | Ameaça | Proteção | Status |
|--------|--------|----------|--------|
| Electron → Node Core | Token de sessão em env var | Bearer header | ✅ Adequado |
| Node Core → Python | Token via env herdado | Bearer header | ✅ |
| Extension install | SSRF, download malicioso | DNS check, HTTPS only, registry validation | ✅ Excelente |
| Extension workers | Código não confiável | Fork + module allowlist | ✅ Bom |
| WebSocket auth | Token vazado em URL | Validação pré-accept + close code | ⚠️ Token prefix logado |
| Renderer → Main IPC | Acesso a canais restritos | Allowlists por categoria | ✅ Bom |
| Renderer (XSS) | Acesso à preload API | contextIsolation + sandbox | ⚠️ IPC genérico exposto |

### Achados de Segurança por Severidade

| Severidade | Count | Descrição |
|------------|-------|-----------|
| Alto | 2 | Token em logs (H-01), sanitizador subutilizado (H-02) |
| Médio | 5 | IPC genérico (M-02), path traversal fraco (M-05), authFetch sem timeout (M-06), `uncaughtException` sem exit (M-07), `message` ignorado em sanitize (M-08) |
| Baixo | 3 | Console.log (M-14), silent catches (L-02/L-03), batch storage sem validação (L-15) |

### Pontos Fortes de Segurança

- SSRF protections multi-camada no sistema de extensões (DNS + IP check + redirect validation + size limits)
- Path traversal protection com canonical containment + double-encoding guard
- Extension workers isolados em processos `fork()` com module allowlist
- Rate limiting por IP (token bucket)
- CORS restrito a origens locais
- Settings PATCH com whitelist de chaves editáveis
